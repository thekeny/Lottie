# GitHub Pages

Сайт — статические файлы, сборка не нужна. При публикации ветки выбери папку `/ (root)`: `index.html`, `404.html`, CSS, `images/` и `fonts/` должны попасть в корень публикации. `.nojekyll` отключает ненужную обработку Jekyll.

GitHub Pages автоматически отдаёт `404.html` с кодом HTTP 404 для несуществующих страниц. Редирект на `/404.html` не нужен: адрес, на котором произошла ошибка, остаётся в браузере.

В `404.html` указан `<base href="/Lottie/">` для проекта `thekeny/Lottie`. Это сохраняет загрузку картинок, CSS, шрифтов и переход домой даже с адреса `/Lottie/missing/deep/page`. При переименовании репозитория измени этот путь. Для собственного домена скрипт переключает базу на `/`, для Live Server — на папку страницы. На GitHub Pages база работает и без JavaScript.

После публикации проверь:

- `/Lottie/` — лендинг;
- `/Lottie/missing/deep/page` — оформленная 404 с картинками;
- «Вернуться домой» — переход на `/Lottie/index.html`;
- в Network у запроса несуществующей страницы статус **404**, у стилей, шрифтов и изображений — **200**.

Локальный просмотр: открой `404.html` через **Open with Live Server**. Live Server показывает файл по прямому адресу; серверную обработку неизвестных URL выполняет GitHub Pages.

Улыбка появляется при наведении на самого Лотти или кнопку домой, а также при клавиатурном фокусе кнопки. Размер места под персонажа фиксирован, поэтому при смене спрайта вёрстка не прыгает.
